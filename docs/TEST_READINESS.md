## 0. 테스트 전에 꼭 해야 하는 공통 준비 (코드 수정 아님)

1. **Google 로그인 (앱 게시 완료, 10/6)**
   - Google Cloud의 OAuth 앱을 **"프로덕션"으로 게시**했어요. 이제 참가자 계정을 테스트 사용자로 **미리 등록하지 않아도** 로그인할 수 있어요.
   - Google 심사를 받지 않은 앱이라 **사용자는 최대 100명**까지예요. 사용성 테스트에는 충분해요.
   - 브랜딩에 넣은 개인정보처리방침 링크: `https://after-life-web-sable.vercel.app/privacy` (배포 사이트에 보이려면 GitHub push 필요)
   - Drive 읽기 권한(`drive.readonly`)을 쓰기 때문에 참가자에게 **"Google에서 확인하지 않은 앱"** 경고가 떠요. 진행자가 "고급 → 이동"을 안내할지, 이 경고 자체를 테스트 관찰 대상으로 볼지 정해야 해요.
2. **Drive 사진 폴더**
   - `afterlife_my data` 폴더가 보이는 계정(공유받았거나 직접 만든 것)은 **그 폴더 안에서** 인물 폴더를 골라요.
   - 그 폴더가 없는 계정은 **자기 "내 드라이브" 전체**에서 고를 수 있어요. 참가자가 따로 준비할 건 없어요 (10/6부터).
   - 참가자 본인 사진으로 테스트하려면, 미리 **내 드라이브에 그 사람의 사진을 모은 폴더 하나**를 만들어 오도록 안내하면 편해요.
   - "내가 남길 기록"은 시작 폴더 바로 안의 **'주인공'으로 시작하는 폴더**(예: `주인공(민경)`)의 사진을 써요. 없으면 만들라고 안내가 떠요.
3. **계정 전략 정하기** (추천)

   - 참가자 새 계정은 캐릭터·책·섹션이 모두 비어 있어서 Task 3~6을 할 수 없어요.

5. **서버: 배포 사이트로 테스트 (공유 링크)**
   - **공유 링크: https://after-life-web-sable.vercel.app** — 링크만 있으면 누구나 들어올 수 있어요 (Vercel 접근 보호 꺼짐, 10/6 확인).
   - 10/6에 GitHub에 push해서 **배포 사이트 = 최신 코드**예요. 이후 고친 내용도 **GitHub Desktop → Push origin**을 해야 배포 사이트에 반영돼요 (push 후 1~2분).
   - 배포 사이트와 로컬은 **같은 데이터베이스(Supabase)**를 써요. 어느 쪽에서 남긴 기록이든 서로 보여요.
   - **Vercel 환경변수는 `.env.local`과 같은 값이어야 해요.** (10/6~7에 6월 값이 남아 있어서 로그인 실패·저장 실패·계정 목록 안 뜸이 생겼고, 모두 맞춰서 해결)
     - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` → 다르면 로그인이 "Google 로그인 중 문제가 생겼어요"로 실패
     - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` → 다르면 인물·기록·Drive 연결이 저장/불러오기 안 됨 (`/api/drive/connections` 를 열면 `fetch failed` 등이 보임)
     - `NEXTAUTH_URL` 은 예외로 배포 주소(`https://after-life-web-sable.vercel.app`), `NEXTAUTH_SECRET`, `GEMINI_API_KEY` 도 등록
     - `NEXT_PUBLIC_`으로 시작하는 값은 **Config** 형식으로, 나머지 비밀 키는 **Secret** 형식으로 저장 (Secret 으로 저장된 `NEXT_PUBLIC_` 값은 고칠 수 없어서 지우고 새로 만들어야 해요)
   - 환경변수를 바꾸면 Vercel **Deployments → 맨 위 ⋯ → Redeploy**를 해야 적용돼요.
   - 배포 사이트 점검: 로그인한 브라우저에서 `https://after-life-web-sable.vercel.app/api/drive/connections` 를 열어 `{"connections":[...]}` 가 나오면 데이터베이스 연결 정상.
   - 배경음악은 64kbps로 줄인 `public/sounds/bgm1.m4a`(약 27MB)를 써요. 원본 `bgm1.mp3`(136MB)는 GitHub 한도를 넘어 올리지 않아요.

### Quick Exit, 블러, 노출 강도는 어디에? (추가 확인 항목 답)
- **Quick Exit:** 책장·책·리캡의 오른쪽 위 "✕ 중단하기 Esc" 버튼 + Esc 키. 글을 적는 중이거나 설정 창이 떠 있으면 Esc는 그쪽에 먼저 쓰여요.
- **흐림 (10/8):** "보고 싶지 않은 기록"에 체크한 종류(투병·채팅 캡처·영상)로 분류된 사진만 흐려요. 리캡·책 화면 대표 사진(절반 세기)·저장소 액자 사진 모두 같아요. 눌러서 본 사진은 계속 선명해요. 체크하지 않았거나 "괜찮아요. 모두 볼게요."를 골랐으면 모든 사진이 선명해요.
- **노출 강도:** 리캡 왼쪽 위 👁 조절(5단계), 설정의 인물 편집과 캐릭터 만들기 4단계의 "고인을 떠올릴 때 마음" 슬라이더. 셋 다 같은 값(캐릭터별)이에요.
